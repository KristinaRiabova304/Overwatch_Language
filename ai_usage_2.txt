3. WHAT WAS TAKEN AS IT WAS, WHAT WAS CHANGED, AND WHY
------------------------------------------------------
Claude wrote all of the Stage 2 code, tests and documentation. I did not
edit any file by hand. My part was the decisions below; Claude proposed
each design, and I accepted or chose.

Decisions I made:
- Branch setup: Claude first created the branch as "stage-2"; after
  reading the PDF it pointed out the branch must be "stage2" and created
  from main after Stage 1 is merged. I chose to merge the Stage 1 pull
  request right away (option B) instead of waiting for its review; Claude
  merged it, deleted "stage-2" and created "stage2" from main.
- Function syntax: I accepted "ability" for functions and "gg" for
  leaving a function, and chose that "gg" at the top level sets the
  program's exit code.
- Structure syntax: I accepted "hero" for structures, "spawn Name(...)"
  for creating objects (positional, one value per field), and flex / 🔒
  for field mutability.
- read/print: I accepted read() as an expression and print(...) as a
  statement that always ends with a newline, with both names reserved.
- Semantic rules: I approved the list of 18 rules Claude proposed (no
  implicit conversions, literals take the type they are used as, inner
  blocks may hide outer names, functions see globals declared above them,
  objects are copied by value, lookup order inside member functions, how
  objects print, ...). The README states them as 22 numbered rules.
- Repository: I agreed to remove the tracked Stage 1 PDF.

Per part of the work:

Lexer (lexer.py) and grammar (grammar.ebnf)
  Taken as written: new keywords (ability, gg, hero, spawn, read, print),
  the ",", ".", "->" tokens and string literals with \n \t \" \\ escapes.

Parser and AST (parser.py, ast_nodes.py)
  Taken as written: one function per new grammar rule, new AST nodes.
  Changed during the session (by Claude, after testing):
  - Assignment and call statements were first separate rules; when
    structures added chains (c.center.x = 1; c.center.move(1);), Claude
    changed both to parse the chain first and decide by the next token.
  - Type names became position-aware so that "unknown type" errors point
    at the type, not at the declaration.

Semantic analysis (semantic.py)
  Taken as written, with these changes after Claude probed every rule
  with small valid and invalid programs:
  - A function body now shares its scope with the parameters, so a local
    cannot redeclare a parameter.
  - Added a clearer error for a field whose structure is declared later.
  - Fixed message wording (plurals such as "1 value", "the condition must
    be ult", quoting of "a spawned object").
  - Stage 1 test error/unknown_type.expected changed: "mystery" used to be
    a syntax error; now any name may be a structure type, so the semantic
    pass rejects it with "unknown type 'mystery'" at the same position.

Code generation (codegen.py) and compiler.py
  Taken as written, with these fixes found by running compiled programs:
  - llvmlite's declare_intrinsic gave the wrong result type for
    llvm.sadd/ssub/smul.with.overflow, so the compiler crashed on checked
    operators; Claude declares those intrinsics by hand.
  - That crash printed a Python traceback; Claude added a last-resort
    handler so even an internal compiler bug is one "compilation error"
    line.
  - An overflow message could appear before output printed earlier
    (stdout is buffered); the runtime trap now flushes stdout first.
  - An empty structure printed as "E {  }" (two spaces); fixed to "E { }".

Tests (tests/)
  Taken as written. Claude wrote the expected output of every end-to-end
  test by hand rather than recording the compiler's output, and checked
  that the runner fails when an expected output or exit code is wrong.
  The runner was extended with the end-to-end suite (clang, NAME.in,
  NAME.exitcode) and now passes an output path for error tests.

README.md, requirements.txt, .gitignore
  Taken as written. Claude compiled every README example and checked that
  every test the README names exists. After checking the install step it
  added a virtual-environment alternative for Pythons where pip refuses
  system-wide installs. When first editing .gitignore Claude overwrote it
  without reading it and dropped the "*.pyc" line; it noticed and put the
  line back.


4. WHAT I UNDERSTOOD (IN MY OWN WORDS)
--------------------------------------
The compiler first learns about all the functions, so that they can call
each other in any order.
In memory, the fields of an object lie one after another. The compiler
finds a field not by its name but by its position number.
A member function gets the address of the object, so that it changes the
original and not a copy of it.
The checked operator adds the numbers, but if the result is too big, the
program stops with an overflow error.
